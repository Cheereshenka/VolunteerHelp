# Проектные решения

## Архитектура

Модульный монолит: HTTP-слой → сервисы → Spring Data JPA → H2. DTO отделяют внешний контракт от JPA-модели.

## Основные сущности

`AppUser` — учётная запись; `VolunteerProfile` — профиль исполнителя; `ServiceRequest` — поручение заказчика; `Booking` — выбранный исполнитель и интервал; `Review` — отзыв; `AuditEvent` — журнал операций.

## Бизнес-правила

- заявка не может иметь прошлую дату или пустой интервал;
- бронирование разрешено только подходящему активному волонтёру;
- активные интервалы одного волонтёра не пересекаются;
- отменённая заявка отменяет её активные бронирования;
- начать поручение может участник соответствующего бронирования;
- завершить поручение может назначенный волонтёр или администратор;
- отзыв доступен заказчику после завершения и только один раз;
- рейтинг волонтёра пересчитывается после нового отзыва;
- изменение бронирования и аудит выполняются в транзакции.

## Конкурентный доступ

При создании бронирования запись `VolunteerProfile` блокируется `PESSIMISTIC_WRITE`. После получения блокировки заново проверяется список активных бронирований. Это сериализует операции, конкурирующие за одного волонтёра.
